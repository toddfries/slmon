## What it is

Native Perl Starlink monitor. Unofficial, not affiliated with SpaceX. No Docker. Code, pages, and wording in this tree are original. Other projects are documentation, opened only to troubleshoot something this tree is already doing. They are not a feature list and they are not named here. When a request is outside this monitor, stop and ask whether this session is the right place before writing a file or a note. The dish service is `SpaceX.API.Device.Device`, rpc `Handle`.

One checkout, several processes, libc `imsg` between them. SQLite by default, PostgreSQL optional, same DML. OpenBSD. Perl 5.42. The dish child uses the in-tree Perl client. `dish_client = xs` loads `Dish.so` after `fork`, and only when the build asked for it with `WITH_DISH_XS=yes`. The default build does not link `libgrpc++`.

## Processes

`ps` titles: `sld: parent`, `sld: dish`, `sld: db`, `sld: http`, `sld: watchdog`, `sld: weather`. `rcctl check sld` matches `sld: parent` with `pgrep -xf`. Assigning `$0` is reported as `perl: sld: parent`. `proc_title` calls `setprogname("sld")` and then `setproctitle` through `SLMON::Imsg`, because this libc always prefixes the program name and does not treat a leading `-` as a request to skip that prefix.

`sld` checks the database, then forks and `setsid`s unless `-F`. The short-lived parent `_exit`s. `SIGHUP` re-reads `/etc/sl.conf`. `listen`, dish, watchdog, and weather apply by restarting those children. Retention, `rollup_interval_s`, and `log_level` are sent to the db child. `db`, `db_path`, and `pg_*` changes are logged and wait for `rcctl restart sld`. A bad file is logged and the running configuration stays. Parent forks and restarts children. If the db child dies, the parent exits non-zero. Dish child never forks. It calls `SLMON::DishWire` unless `dish_client` is `xs`, and then it is the only process that loads `SLMON::Dish`. A change to `dish_host`, `dish_interval_s`, or `dish_client` restarts that child. Parent `use`s `DishProc` and `Http` before fork so the children are not the first to compile them. `DishProc` loads `DishWire` at compile time and does not load `SLMON::Dish` unless the client is `xs`. A child that dies inside `_spawn` is warned as `sld: NAME: …` and restarted.

`SLMON::IMSG_MAX` is 262144, not 16KB. History still goes in chunks of at most 30 samples. The obstruction map is one message; a map larger than the max is a hard error. The procedure for another Perl daemon is the user skill `imsgify` at `~/.grok/skills/imsgify/SKILL.md`. This tree keeps `SLMON::Imsg` and its message numbers.

Commands: `sld` (daemon), `sld -F` (foreground), `sld -n` (config check), `slctl init`, `slctl passwd`, `slctl status` (read-only db), `slctl once` (one status JSON, no db write, no pledge). Flags `-c`, `-d`, `-l`. `slctl init` refuses uid 0 with `slctl: doas -u _sl slctl init`. A second `init` prints `slctl: already initialized` and does not change the password. `slctl passwd` prompts the same way on an existing database, replaces the admin user, the password, and the session key, and prints `slctl: admin user reset` and `slctl: rcctl restart sld`. Its database child only writes settings. It does not roll up. SQLite `temp_store` is `MEMORY` because the database child unveils only the state directory, and a sort that spills to `/tmp` is reported as `disk I/O error`. The running `sld` keeps the old session key until that restart. `passwd` on a missing database exits non-zero, prints the `init` hint, and does not create the file. Uid 0 is refused with `slctl: doas -u _sl slctl passwd`. Unknown config keys are rejected. `db=pg` without `pg_db` is rejected.

`rc.d/sld` is `/etc/rc.d/sld` when installed. `daemon=/usr/local/sbin/sld`, `daemon_user=_sl`, `daemon_flags="-c /etc/sl.conf"`. `pexp="sld: parent"` is assigned after `. /etc/rc.d/rc.subr`. That file replaces `pexp` with the daemon path and flags. Start writes the pattern it saw to `/var/run/rc.d/sld`, and stop reads it back, so `rc_check` sets `sld: parent` again. A pattern assigned before the source is what made `rcctl stop sld` exit 0 while the parent kept running. `rc_bg` is unset because `sld` forks itself.

## Dish

Insecure gRPC to `host:9200`, 5s deadline, after a 2s TCP probe. Channel is created in the dish child. `SLMON_DISH_CMD` replaces the real dish (regress). The double must see `SLMON_DB_FD`. `regress/fakedish.pl` writes one scripted minute and exits on its first start so the parent restarts it; later starts stay up. It also upserts `dish_info` and inserts a metrics row. A test daemon pointed at a copy of the live db will show that fake dish on the stat tiles.

Live map samples are about 123×123 little-endian floats: mostly `-1` (unmeasured) or `1` (clear), a few `0` (blocked). Do not claim a north-up orientation.

`seconds_to_first_nonempty_slot` has come back as a unix timestamp (~1.79e9), not a small duration. `legacy_state` is often null on this firmware.

## Storage

Default database is `/var/sl/sl.db` (`db_path` in `/etc/sl.conf`). The directory is mode `0700`, owner `_sl:_sl`. `sld` does not create `/var/sl`. WAL, `synchronous=NORMAL`, `busy_timeout=5000`, `temp_store=MEMORY`, mode `0600`. Override with `-d`. PostgreSQL is `db=pg` plus `pg_*` keys. Dialect is confined to `SLMON::DB::SQLite` and `SLMON::DB::Pg`.

Time columns used by queries: `history_samples.ts`, `metrics.ts`, `metrics_minutely.ts_minute`, `metrics_hourly.ts_hour`, `metrics_daily.ts_day`, `events.ts`, `dish_info.last_seen_ts`, `obstruction_map.ts`, `weather.ts`, `speedtests.ts`, `alert_queue.created_ts`. Query ops are only `latest` and `raw`. Obstruction SNR is returned as `snr_b64` (the blob is stripped). Row chunks over imsg are about 200000 bytes.

`history_samples` is unique on `(run_id, dish_counter)`. A new run starts when bootcount changes or the tip counter moves backwards. Drop rate ≥ 1 stores NULL latency.

Rollups run in the db child. Byte columns are `sum(bps)/8`. An empty minute roll does not advance the cursor; the newest completed minute stays open. `roll_minutes` copies obstruction from `metrics` in that minute (`avg_obstr_fraction`, `max_obstr_fraction`) and stores `jitter_ms` as max `ping_latency_ms` minus min in that minute. NULL latencies are ignored. Hour and day rows average the finer obstruction averages, take the max of the finer maxima, and store jitter as the finer max latency minus the finer min latency. That spread is not an average of the finer jitter values. `history_samples` has no obstruction column. Do not invent one.

An existing database does not grow columns from `CREATE TABLE IF NOT EXISTS`. `SLMON::DB::_migrate` runs `ALTER TABLE` at schema init: `jitter_ms` on the three rollup tables, plus `max_obstr_fraction` and `min_ping_latency_ms` on the hour and day tables. The first rollup after that fills stored rows whose source samples are still in the database. `log_level` is `info` (default) or `debug`. Debug logs rollup bucket counts and which table a chart read, including the hourly tail on `365d` and `ever`. It does not log the session secret, the password, or `pg_password`.

Retention, in `SLMON::Rollup::retain`: raw history and `metrics` older than 90 days compressed into hourly, then deleted. That compression reads obstruction from `metrics` and jitter from the history latencies before the delete. A conflicting hourly row keeps the throughput already stored and fills a NULL obstruction or jitter. Hourly older than 365 days averaged into daily then deleted. Minutely older than 730 days deleted. Config key for the raw window is `raw_retention_days`. `events`, `weather`, `speedtests`, and `alert_queue` are not aged. `obstruction_map` is a single row. `speedtests` and `alert_queue` have schema and no writer. `metrics_daily` stays empty until an hourly row is old enough. Weather stays empty until lat/lon are set. None of those are unfinished collection.

## HTTP

Listener default `127.0.0.1:8080`. `listen` may be repeated. Each value is `host:port` or `[ipv6]:port`. The parent binds every line and the http child inherits the sockets that bound. A failed line is logged with the address and the error. The others keep serving. A reload that binds nothing keeps the previous sockets. `http.port` is one port per bound address. Debug logs each attempt and whether it bound. `-l` replaces the whole list for that process. One request per connection, `Connection: close`, 5s read timeout. The http child never opens the database. It asks the db child. Pledge is `inet` only, after modules load. `strftime`/`localtime` are warmed in `Http::run` before that pledge (`strftime('%H:%M', localtime($^T))`). `page_rev` is computed in that same stretch, before pledge, because `stat` of the page modules needs the filesystem. `gmtime` is safe after pledge. HTML and its script are inline because the pledge has no filesystem. No static files and no CDN.

- `GET /health` — open JSON `{ok, rev}` with `Cache-Control: no-store`. `rev` is eight hex digits. It mixes the size and mtime of `SLMON/Dash.pm`, `SLMON/Http.pm`, and `SLMON/Config.pm` with the configuration the page shows (dish host and port, sample interval, chart interval, map interval, database, listen, retention days). It is taken when the http process starts. A newer file, or a config change, is visible after that process is restarted. The password, the session secret, and `pg_password` are not part of it.
- `GET /` — no session redirects to `/login`. With a session, `SLMON::Dash::page`. The page links `GET /export.csv?range=` for the current window.
- `GET /export.csv` — same session and the same five windows. The body is the rows that window already reads, including the hourly tail on `365d` and `ever`, as CSV. A null byte is an empty cell. No session redirects to `/login`. There is no delete.
- `GET /login`, `POST /login` — form fields `user`, `password` (ids `user`, `password`). Failure is 401 HTML, username kept and escaped. `POST /api/login` and `POST /api/logout` stay JSON.
- `POST /logout` — clears the cookie, redirects to `/login`.
- `GET /api/latest/TABLE`, `GET /api/raw/TABLE?from&to&limit&order` — cookie required. Default limit 5000, max 50000. Allow-listed tables only.
- No delete request. No static files.
- Install, no session: `GET /manifest.webmanifest`, `GET /sw.js`, `GET /icon-192.png`, `GET /icon-512.png`. The worker's fetch handler calls `fetch(event.request)` and does not use `caches`. The Install button is in the header, hidden until `beforeinstallprompt`. Install works on `127.0.0.1` and `localhost`. The installed window opens at `/`. Icons are PNGs built in the process (stored deflate, no zlib module) and cached in that process.

Cookie `slmon_session`: HMAC-SHA256, 12h, HttpOnly, SameSite=Lax, Path=/, Max-Age=43200. Password check stays in the db child. Five failures per IP per five minutes.

Dashboard ranges: `?range=24h|7d|30d|365d|ever`, default `24h`, invalid including old `1h` and `6h` falls back to `24h`. `24h` reads `metrics_minutely`. `7d` and `30d` read `metrics_hourly`. `365d` and `ever` read `metrics_daily`, then keep an hourly row whose UTC day has no `ts_day` row (the open day, and any day not rolled yet). `ever` sends no lower time bound. The chart axis for `ever` starts at the earliest drawn point, not unix 0. Clock labels: `24h` is `%H:%M`, `7d` and `30d` are `%m-%d`, `365d` and `ever` are `%Y-%m-%d`. Obstruction uses the series when the tier has a fraction, including a stored zero. Otherwise the chart reads `metrics` (limit 20000). Raw metrics are kept 90 days, so that fallback covers only the recent part of `365d` and `ever`. Jitter is `jitter_ms` on the same rows. One page, no tabs: `#overview` (latest rates, loss, latency, obstruction, uptime), `#quality` (packet loss, latency, jitter, obstruction), `#throughput` (bytes down, bytes up, and their sum, then downlink and uplink), `#dish` (identity, azimuth, elevation, SNR, GPS, alerts, grid; a note when no map is stored), `#history` (events), then configuration. The window nav sits inside `#live`. The page shows that configuration: dish address, sample interval, chart interval, obstruction map interval, listen address, database kind, and retention days. Charts sit in `#live` and are replaced in place every `dish_interval_s` seconds (default 30, minimum 2). `dish_interval_s` below 2 is rejected. The same script asks `/health` every 2 seconds and reloads the whole page when `rev` differs. Neither timer runs faster than 2 seconds. The login page runs the revision check and has no `#live`, so it does not redraw charts. Logout stays in the header, outside `#live`. Downsample above 480 points. Y axis starts at 0 with a 1/2/5/10 max. Missing numbers render as ASCII `n/a`. A UTF-8-flagged em dash breaks `Content-Length` because that header uses character length. The degree sign in azimuth/elevation is raw UTF-8 bytes in the source, without `use utf8`, so the string stays bytes. Stale if the latest sample is older than 120s. Alert names come from `SLMON::StatusMap::alert_names` (`motors_stuck` is bit 1, value 2). Map: `unpack('f<*')`, class `u` unmeasured, `o` blocked (any 0 in a downsample block stays blocked), `c` clear. When no map is stored, Dish says so instead of drawing a grid. When azimuth and elevation are known, a ring on that grid is the boresight: north is up, azimuth 0 is north, elevation 90 is the center, and elevation 0 is the horizon. `#history` opens with an outage calendar for the selected window. `ping_ok` is not an outage. A window with no other events says so.

Unit tests of `GET /` pass `$ctx->{dash}` because they have no imsg. A query error still renders the page, including the escaped user, with "The database did not answer."

`browse.mjs --type` splits on the first `=`. Use `input#user`, not `input[name=user]`. `--click` does not wait for navigation. HttpOnly cookies show up in the cookie jar, not `document.cookie`. Favicon 404 is harmless.

A process started before a code change keeps the old HTTP behavior until that process is restarted. Do not kill a collector you did not start. As of this writing the checkout's collector was pid 26399, started 2026-10-18 11:45, cwd this repo, database `var/slmon.db`. The pid will change.

## Pledge

- Parent pledge is wide enough, including `unveil`, that a restarted child can still narrow itself.
- Dish, Perl client: `inet dns rpath`, then unveil `/dev/urandom`, resolver files, `/etc/hosts`, `/etc/services`, `/etc/protocols`. The XS client adds `prot_exec` because `Dish.so` and abseil load code. If unveil or pledge fails, the dish child logs and keeps running unpledged. That is the current behavior.
- Db: unveil the state directory. Then `rpath wpath cpath flock recvfd`, plus `unix` for PostgreSQL.
- Http: `inet` only.
- Watchdog: `proc exec inet`, ping is OpenBSD `ping -c 1 -w 2 -n`. There is no `head -c` on this host.
- Weather: `inet dns rpath`, and it already uses `IO::Socket::SSL`.

## 2026-11-23 obstruction behavior

The Dish section shows the latest fraction, whether the dish is currently obstructed, the prolonged duration, and the prolonged interval. The numbers are the latest `metrics` row (`obstr_fraction`, `currently_obstructed`, `obstruction_duration`, `obstruction_interval`). They are not a second series and they are not rolled up. Seconds obstructed and the patch count stay in the plan catalog.
